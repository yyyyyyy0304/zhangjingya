    USER {
        string user_id PK "用户主键"

    SESSION {
        string session_id PK "会话主键"

    }
    MESSAGE {
        string message_id PK "消息主键"
        string session_id FK "所属会话"
        string role "user / bot / agent"
        text content "消息内容"
        datetime sent_at "发送时间"
    }
    INTENT {
        string intent_id PK "意图主键"
        string intent_name "意图名称"
        float confidence "识别置信度"
        string parent_id "父级意图"
    }
    KNOWLEDGE_ITEM {
        string kb_id PK "知识条目主键"
        string intent_id FK "对应意图"
        string question "标准问题"

        string version "版本号"
        int hit_count "命中次数"
    }
    TICKET {
        string ticket_id PK "工单主键"
        string session_id FK "来源会话"

        string status "待处理 / 处理中 / 已关闭"

    AGENT {

    FEEDBACK {
        string feedback_id PK "反馈主键"
        string ticket_id FK "关联工单"
        string user_id FK "评价用户"

        string comment "文字评价"
    }

为什么用 Mermaid

图的结构写成纯文本，改动业务节点只需改几行代码；渲染结果直接是 SVG， 缩放不失真，也方便贴进文档与 PPT。

流程图要点

四个 subgraph 把接入、理解、服务、运营分开；菱形节点表示分支判断， 低置信度自动转人工，澄清追问可回到意图识别形成闭环。

ER 图要点

会话与消息是一对多，消息归属某个意图；知识条目按意图组织并由坐席维护； 一次会话最多生成一个工单，工单与评价形成反馈数据。
